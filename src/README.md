# Лабораторная работа №4. Асинхронный исполнитель задач
### Выполнила: Китаева Дарья М8О-102БВ-25

## Цель работы
Научиться реализовывать приложения с асинхронной моделью управления.

## Постановка задачи
Реализовать асинхронный исполнитель задач, обрабатывающий задачи из очереди с использованием расширяемых обработчиков.

## Функциональные требования
- асинхронная очередь задач;
- описание контракта обработчика через Protocol;
- использование контекстных менеджеров для управления ресурсами;
- централизованное логирование и обработка ошибок.

## Технические требования
- корректное использование async / await;
- отсутствие блокирующих операций в event loop;
- архитектура, допускающая добавление новых типов задач и обработчиков;
- аннотации типов и документация.

## Что реализовано
В проекте реализованы:
- класс Task для хранения информации о задаче;
- класс AsyncTaskExecutor для асинхронного выполнения задач;
- протокол TaskHandler для описания контракта обработчиков;
- обработчики PrintHandler и PriorityHandler для демонстрации расширяемости;
- контекстный менеджер для управления ресурсами исполнителя;
- централизованное логирование через logging;
- демонстрационная программа в main.py;
- тесты для асинхронного исполнителя.

### Класс AsyncTaskExecutor
Асинхронный исполнитель задач.

Поддерживает:
- асинхронную очередь задач (asyncio.Queue);
- регистрацию обработчиков через register_handler();
- параллельную обработку задач несколькими воркерами;
- ленивую загрузку задач из источников;
- сбор статистики выполнения.

### Протокол TaskHandler
Определяет контракт для всех обработчиков задач:
- can_handle(task) - проверяет, может ли обработчик выполнить задачу;
- handle(task) - выполняет задачу.

## Вывод
В ходе лабораторной работы был реализован асинхронный исполнитель задач. Использование asyncio.Queue позволило организовать неблокирующую очередь задач. Протокол TaskHandler обеспечивает возможность расширения системы новыми типами обработчиков без изменения существующего кода. Контекстный менеджер гарантирует корректное управление ресурсами при запуске и остановке исполнителя. Централизованное логирование позволяет отслеживать процесс выполнения и ошибки. Асинхронная архитектура с несколькими воркерами обеспечивает эффективную параллельную обработку задач без блокировки event loop.
